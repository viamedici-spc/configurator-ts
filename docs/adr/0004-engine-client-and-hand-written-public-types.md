# ADR 0004: Wire types from openapi-typescript, requests through openapi-fetch, public types written by hand

Date: 2026-11-26

## Context

The engine client was generated by swagger-typescript-api: a class with one method per operation, plus runtime code.
The public error types and the package model types were derived from its wire types, so a regenerated client — a newer
engine contract or another generator — changed the public API (new fields such as `status`, `| null` on optional
fields, index signatures). Keeping hand-written types in step with the engine is cheap now that coding agents do most
of that maintenance.

## Decision

- `scripts/generate-engine-types.ts` (its own Bun package in `scripts/`) generates `src/apiClient/engine/Engine.ts` with
  openapi-typescript: types only, string unions instead of enums, one alias per schema.
- `src/domain/EngineApiClient.ts` sends the requests with openapi-fetch, one function per operation the library uses.
- Public types never derive from wire types: `src/contract/ConfiguratorError.ts` and the package model types in
  `src/contract/Types.ts` are written by hand; `src/domain/mapper/` translates, field by field.

## Consequences

- A change of the engine's contract shows up as a type error in the mappers, not as a silent change of the public API.
- Public error objects carry only their declared fields; their properties are readonly.
- The generator needs TypeScript 5's compiler API while the library builds with TypeScript 7; installs are isolated per
  workspace package (`linker = "isolated"` in `bunfig.toml`).

## Alternatives considered

- **Keep swagger-typescript-api:** generated runtime code and derived public types are what this decision removes.
- **@hey-api/openapi-ts:** a function SDK closer to the old call style, but more generated code and a plugin system of
  its own, still before its 1.0.
- **Derive the public types from the new wire types:** would carry the generator's shapes into the public API.
